# 로컬 저장 큐와 메모 성운

## 현재 동작

서버는 아직 연결하지 않았습니다. 메모는 IndexedDB에 저장되며 `pending`을 유지합니다. `navigator.onLine`은 전송 시도 조건이며 서버 저장 성공의 증거로 사용하지 않습니다.

`MemoOrbitDB` 버전 2는 `memos`, `syncQueue`, `settings` 저장소를 사용합니다. 메모 변경과 전송할 최신 수정본을 같은 트랜잭션에 기록합니다. 삭제도 `operation: delete`인 큐 항목으로 보존합니다. 기존 메모는 첫 로드에서 전송 대기로 전환합니다. 초기 데이터 전체 삭제 후에는 기본 데이터를 다시 넣지 않습니다.

작성 모달은 로컬 저장 완료 후 닫힙니다. IndexedDB 오류 시 LocalStorage 백업을 사용하고, 둘 다 실패하면 오류를 알리고 편집기를 유지합니다. 복구 시 백업을 먼저 읽으며 백업이 남아 있는 동안 서버로 예전 DB 내용을 전송하지 않습니다. 브라우저 데이터 삭제나 기기 저장 공간 소진까지 막는 원격 백업은 아직 제공하지 않습니다.

## 서버 연결 계약

서버 구현 후 `NEXT_PUBLIC_MEMO_SYNC_ENDPOINT=/api/memos/sync`처럼 **같은 출처 경로**를 설정하고 앱을 다시 빌드합니다. 이 경로는 설정 예시이며 현재 프로젝트에 가짜 성공 API를 만들지 않았습니다. 테스트에서는 `startSyncQueue`에 `SyncTransport`를 직접 주입할 수 있습니다.

클라이언트는 동일 출처 인증 쿠키를 포함해 POST 요청을 보냅니다. 공개 환경 변수에는 API 키나 토큰을 넣지 않습니다.

```json
{
  "id": "memo-id",
  "revision": "수정본 UUID",
  "operation": "upsert",
  "memo": { "id": "memo-id", "title": "메모", "syncStatus": "pending" },
  "attempts": 0,
  "nextAttemptAt": 0,
  "queuedAt": 0
}
```

실제 `memo`에는 본문·날짜·태그·첨부·링크 등 전체 메모 필드가 들어갑니다. 삭제 요청에는 `memo`가 없습니다. `Idempotency-Key` 헤더에도 같은 `revision`을 보냅니다.

서버는 인증·소유권 검사, 영구 저장, 수정 충돌 정책과 멱등 처리를 구현한 뒤에만 다음 2xx JSON 응답을 반환해야 합니다.

```json
{ "revision": "요청과 동일한 수정본 UUID" }
```

클라이언트는 같은 수정본의 확인 응답만 `synced`로 반영합니다. 잘못된 응답과 네트워크 오류는 `failed`로 남기고 최대 5분의 지수 지연으로 재시도합니다. 온라인 재연결·앱 시작·5초 주기 검사로 큐를 처리하며 요청당 20초 제한을 둡니다. 지원 브라우저에서는 Web Locks로 탭 간 전송을 직렬화합니다. 미지원 환경의 중복 전송도 서버의 멱등 처리로 흡수해야 합니다.

앱을 완전히 닫은 동안 실행하는 서비스 워커 동기화나 여러 기기 간 서버 변경 내려받기는 이번 범위에 포함되지 않습니다.

## 성운 캔버스

저장된 `Memo.links.weight`를 0~1 범위로 검사하고 0.75 이상 링크의 연결 집합을 성운으로 묶습니다. 높은 점수는 짧은 목표 거리로 당기고 낮은 점수는 추가 반발력을 적용합니다. 미분석 쌍에는 충돌 방지 반발력만 적용하며 AI 점수를 만들어 넣지 않습니다.

`orbitClustering.ts`는 초기 배치와 물리 계산, `orbitCanvas.ts`는 그리기, `OrbitGraphView.tsx`는 수명·선택·제스처를 담당합니다. 180단계를 프레임마다 한 단계씩 계산한 뒤 정지하며 노드당 최대 네 개의 강한 선만 그립니다. 두 손가락 중점을 기준으로 확대·이동하고 취소·드래그는 탭과 구분합니다.

기존 `gemini-1.5-flash` 서버 분석을 유지합니다. 모델/API 실패 시 안내를 표시하고 저장된 연결만 사용합니다. 한 요청은 최대 500개 메모·1500개 희소 관계를 분석하며, 500개 초과 시 50개씩 겹치는 묶음으로 순차 요청합니다. 모든 쌍의 유사도를 계산하는 완전 그래프가 아니므로 서로 다른 묶음 사이의 관계를 모두 찾는 것은 아닙니다.
